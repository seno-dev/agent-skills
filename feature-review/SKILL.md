# feature-review

thermos と interrogate は既定でブランチ差分（main...HEAD）しか見ないため、差分の外にある設計の穴を見落とす。この skill は機能全体を対象にする。

## 対象
- 指示文で指定された機能の全体（入口から外部サービス、DB、webhook、バッチ、管理画面まで、その機能の状態に触れるコードすべて）。差分に限らない。
- 対象に入れたファイルと、入れなかった範囲を最初に書く。
- 状態遷移が込み入っていれば、`statechart` skill で TLA+ モデルを作って確かめてよい。

## 毎回の問い
機能の状態ごとに、次の 5 つを必ず問う。
1. 誰も気づかない漏れ: 課金漏れ、未通知、記録されない失敗など、エラーにならず静かに起きるもの。
2. 永久に止まる状態: 未確定のまま誰も進めない照会や処理、タイムアウトや再試行がない待ち。
3. 重複している状態: 同じ対象を指す値の二重持ち、ID の再利用や並行実行で起きる競合、二重処理。
4. もっと簡単にできる形: 状態や分岐を減らせる設計。
5. もう要らない仕組み: 使われていない経路、役目を終えたフラグや fallback。

## 指摘の書き方
指摘ごとに次を書く。
- 場所: `パス:行`
- 問題: 何が起きるか（起きる条件と手順）
- 簡単な形: 直す方向
- 影響: お金、データ、利用者への影響
- 確度: 確定（コードかテストで再現・確認済み）か推測か

## 終わり方
- 最後に、影響の大きい順に並べた一覧で終える。
- 報告だけで、コードは修正しない。
